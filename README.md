# یادداشت کتاب‌ها

سایت ساده و بدون نیاز به بیلد برای نگهداری خلاصه‌ی کتاب‌ها، با Markdown و Git.

## ساختار پروژه

```
.
├── index.html      فهرست همه‌ی کتاب‌ها
├── book.html       صفحه‌ی نمایش خلاصه‌ی یک کتاب
├── style.css       استایل مشترک
├── app.js          توابع خواندن و پارس فایل‌های Markdown
├── robots.txt      اجازه‌ی کراول به موتورهای جست‌وجو
├── sitemap.xml     نقشه‌ی سایت برای گوگل
└── books/
    ├── books.json
    ├── build_index.py
    ├── md_converter.py
    ├── radical-candor/
    │   ├── radical-candor.md
    │   ├── cover.webp
    │   └── 01.webp
    ├── leaders-eat-last/
    │   ├── leaders-eat-last.md
    │   └── cover.webp
    └── propaganda/
        ├── propaganda.md
        └── cover.webp
```

## افزودن کتاب جدید

۱. یک پوشه در `books/<اسلاگ-کتاب>/` بساز و فایل Markdown را به نام همان اسلاگ داخلش قرار بده؛ مثلاً `books/1984/1984.md`

۲. این ساختار را رعایت کن:

```markdown
---
title: عنوان کتاب
author: نام نویسنده
category: توسعه فردی
year_publish: 2018
date_updated: 1404/03/01
read_minutes: 10
rating: 4
tags: [تگ۱, تگ۲]
quote: یک نقل‌قول کوتاه و مورد علاقه از کتاب
---

## خلاصه
متن خلاصه...

## نکات کلیدی
- نکته اول
- نکته دوم

## برداشت من
- برداشت اول
- برداشت دوم
```

فقط `title` لازم است؛ بقیه فیلدها اختیاری‌اند و اگر خالی بمانند، به سادگی نمایش داده نمی‌شوند.

نکات درباره‌ی فرمت:
- `read_minutes` را می‌توانی فقط عدد بنویسی (مثلاً `12`؛ خودکار می‌شود «۱۲ دقیقه») یا عبارت کامل (مثلاً `1 ساعت و 20 دقیقه`؛ همان‌طور که نوشتی نمایش داده می‌شود).
- `year_publish` سال انتشار خود کتاب است (مثلاً ۲۰۱۸)، و `date_updated` تاریخ آخرین تغییر در متن خلاصه است (به‌صورت `سال/ماه/روز`، مثلاً `1404/03/01`). کتاب‌ها در صفحه‌ی اصلی بر اساس همین تاریخ مرتب می‌شوند: جدیدترین بروزرسانی اول. کتابی که `date_updated` نداشته باشد آخر لیست می‌آید. هر بار متن یک خلاصه را عوض کردی، این تاریخ را هم عوض کن.
- `category` برای دسته‌بندی و فیلتر کتاب‌ها در صفحه‌ی اصلی استفاده می‌شود.
- عنوان بخش‌های `## خلاصه`، `## نکات کلیدی` و `## برداشت من` (یا `برداشت شخصی`) به‌طور خودکار با طراحی ویژه (شماره‌گذاری دایره‌ای، تیک) نمایش داده می‌شوند؛ هر عنوان دیگری هم به‌شکل یک بخش ساده رندر می‌شود.
- اگر فیلد `cover` را ندهی، جلد هر کتاب به‌صورت خودکار و بر اساس نام فایل رنگ‌آمیزی می‌شود.

۳. فهرست کتاب‌ها (`books.json`) را بازسازی کن:

```bash
python3 books/build_index.py
```

این اسکریپت پوشه‌های داخل `books/` را بررسی می‌کند و از فایل `<اسلاگ>/<اسلاگ>.md` مشخصات هر کتاب را در `books/books.json` می‌نویسد؛ صفحه‌ی اصلی فقط همین فایل کوچک را دانلود می‌کند، نه متن کامل همه‌ی کتاب‌ها. بنابراین با زیاد شدن کتاب‌ها هم سریع می‌ماند. هر بار فرانت‌متر یک کتاب را هم عوض کردی (مثلاً `date_updated`) باید دوباره اجرایش کنی. فایلی که اسمش با `_` شروع شود (مثل `_draft.md`) نادیده گرفته می‌شود. اگر فایل `.github/workflows/build-index.yml` را در ریپو داشته باشی، گیت‌هاب بعد از هر push همین کار را خودکار انجام می‌دهد.

۴. تغییرات را کامیت و پوش کن:

```bash
git add .
git commit -m "add: خلاصه‌ی 1984"
git push
```

۵. (اختیاری ولی برای سئو مفید) اسلاگ کتاب (اسم فایل بدون `.md`) را به `sitemap.xml` هم اضافه کن، دقیقاً به همون شکل که بقیه‌ی کتاب‌ها اونجا هستن:

```xml
<url>
  <loc>https://shiyasi.ir/book.html?b=1984</loc>
  <changefreq>monthly</changefreq>
  <priority>0.8</priority>
</url>
```

## افزودن عکس جلد برای یک کتاب

عکس‌های هر کتاب در پوشه اختصاصی همان اسلاگ نگهداری می‌شوند: `books/<اسلاگ-کتاب>/`.

۱. کاور را با نام `cover.webp` داخل پوشه کتاب بگذار:
```
books/atomic-habits/cover.webp
```

۲. برای افزودن کاور دیگری نیازی به تغییر فرانت‌متر نیست؛ فقط نام فایل را همان `cover.webp` نگه دار.

۳. فایل `books.json` را بازسازی کن:
```bash
python3 books/build_index.py
```

۴. تغییرات را کامیت و پوش کن.

نکات:
- حجم هر جلد را زیر ۱۰۰ کیلوبایت نگه دار. WebP با کیفیت ۸۰ معمولاً ۳۰ تا ۶۰ کیلوبایت می‌شود. عکسی که بزرگ‌تر از ۸۰۰ پیکسل ارتفاع باشد فقط سنگین‌تر می‌شود و تفاوتی ندارد.
- اگر نسبت عکس ۳:۴ نباشد، لبه‌هایش بریده می‌شود.
- وقتی `cover` داری، سایت عنوان کتاب را روی آن نمی‌نویسد؛ پس عنوان باید روی خود عکس باشد (مثلاً جلد واقعی کتاب).
- اگر عکس جلد واقعی کتاب را از اینترنت می‌گیری، توجه داشته باش که جلدهای کتاب معمولاً کپی‌رایت دارند؛ برای یک آرشیو کاملاً شخصی معمولاً مشکلی پیش نمی‌آید، ولی اگر سایت را عمومی و پرمخاطب می‌کنی بهتر است از عکس‌های خودت یا منابع آزاد (مثل Open Library Covers API) استفاده کنی.
- می‌توانی بعضی کتاب‌ها عکس داشته باشند و بعضی نه؛ هرکدام که `cover` نداشته باشد، همان جلد رنگی خودکار را می‌گیرد.

## دیپلوی روی GitHub Pages

۱. ریپو را در گیت‌هاب بساز و کد را پوش کن.
۲. در تنظیمات ریپو، بخش **Pages** را باز کن.
۳. بخش Source را روی برنچ `main` و پوشه‌ی `/ (root)` بگذار.
۴. سایت روی آدرسی شبیه `https://username.github.io/repo-name/` بالا می‌آید.

> نکته: چون فایل‌های Markdown با `fetch` خوانده می‌شوند، باز کردن `index.html` مستقیم از روی دیسک (`file://`) کار نمی‌کند — باید از طریق یک سرور محلی (مثلا `python3 -m http.server`) یا هاستی مثل GitHub Pages باز شود.

## اجرا روی سیستم شخصی (قبل از پوش کردن)

```bash
python3 -m http.server 8000
```

سپس آدرس `http://localhost:8000` را باز کن.

## گذاشتن عکس داخل خلاصه‌ی کتاب

۱. عکس‌ها را داخل پوشه‌ی خود کتاب بگذار، مثلاً `books/sapiens/map.webp`.

۲. در فایل Markdown همان کتاب، با این قالب بنویس:

```markdown
![توضیح کوتاه درباره‌ی عکس](books/sapiens/map.webp)

![توضیح کوتاه](books/sapiens/map.webp "این متن به‌عنوان زیرنویس زیر عکس نمایش داده می‌شود")
```

- متن داخل `[ ]` (alt) را حتماً بنویس؛ برای سئو و کاربران نابینا مهم است.
- متن داخل `" "` اختیاری است و زیر عکس به‌صورت زیرنویس می‌آید.
- عکسی که خودش یک خط جدا باشد، وسط صفحه با کادر و سایه نمایش داده می‌شود. عکسی که وسط جمله بیاید، کوچک و داخل خط می‌ماند.

نکات:
- عرض عکس را حدود ۱۰۰۰ تا ۱۲۰۰ پیکسل و فرمت `.webp` یا `.jpg` انتخاب کن و قبل از آپلود فشرده‌اش کن؛ عکس سنگین سایت را کند می‌کند.
- نام فایل‌ها را انگلیسی و بدون فاصله بنویس (مثلاً `map-1.webp`).
- از عکس‌های خودت یا منابع آزاد استفاده کن؛ عکس صفحه‌های خود کتاب معمولاً کپی‌رایت دارد.

## سفارشی‌سازی

- رنگ‌ها و فونت در `style.css` (متغیرهای `:root`) قابل تغییرند.
- منطق نمایش و جستجو در `index.html` و `book.html` است؛ چون از هیچ فریم‌ورکی استفاده نشده، تغییر دادنش ساده است.
